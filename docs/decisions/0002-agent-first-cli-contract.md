# 0002. The CLI is an API for agents

Status: Accepted, 2026-10-09

## Context

Most `hall` invocations come from agents: the dev agent in your session, hooks,
and later the assayer and fixer. Agents parse output, can't answer prompts, and
retry. Human-oriented CLIs break all three assumptions.

## Decision

Every command follows the same contract.

- **Output.**
  - JSON when stdout isn't a TTY; `--json` forces it.
  - Readable text only on a TTY.
- **Never prompts.**
  - Destructive actions need explicit flags, such as `drop --reason`.
- **Idempotent.**
  - Repeating a command returns the current result. For example, `ready` at the
    same SHA returns the existing queue entry.
- **`next`.**
  - Every reply carries `next`, the commands that make sense now.
- **Errors.**
  - The shape is `{"error":{"code","message","next"}}`, with stable codes.
  - Exit codes are documented: 0 ok, 1 internal, 2 usage, 3 not found, 4 wrong
    state, 5 gate denied, 6 checks failed, 7 claimed by another agent.
  - clap's usage errors are converted to this envelope with exit 2.
- **Self-describing.**
  - `hall help --json` introspects the clap tree.
  - `hall schema <command|error|event|config>` prints JSON Schema generated by
    schemars from the same Rust types that are serialized.
- **Location-aware.**
  - Inside an item's worktree, the item ID is optional.

## Consequences

- Output types are part of the public API. Their JSON is pinned by insta
  snapshot tests, and changing them is a deliberate act.
- Each reply type has both a text rendering and a JSON rendering.
- Agents can recover from errors without a human, by following `next`.
